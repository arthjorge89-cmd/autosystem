3. UML: diagrama de sequência

O que acontece, em ordem, do agendamento até fechar a OS.

sequenceDiagram
actor C as Cliente
actor R as Recepção
participant P as Site e Painel
participant A as API Flask
participant B as Banco SQLite
C->>P: Agenda pelo site
P->>A: POST /agendamentos
A->>B: INSERT agendamento (Pendente)
R->>P: Confirma o agendamento
P->>A: PUT /agendamentos/:id
R->>P: Abre a OS quando o carro chega
P->>A: POST /ordens
A->>B: INSERT ordem_servico
R->>P: Lança serviços e peças
P->>A: POST /ordens/:id/itens
A->>B: INSERT os_servico e os_peca
B-->>B: Trigger baixa estoque e soma o total
R->>P: Finalizar OS
P->>A: POST /ordens/:id/concluir
A->>B: UPDATE status Concluído
B-->>A: Trigger grava data de saída
A-->>P: OK
P-->>R: OS fechada
C->>P: Consulta o andamento pelo número da OS

4. Arquitetura em 3 camadas

Cada camada só conversa com a vizinha. No protótipo publicado, o navegador guarda os dados (localStorage) no lugar da API e do banco. Em produção, entram o Flask e o SQLite.
